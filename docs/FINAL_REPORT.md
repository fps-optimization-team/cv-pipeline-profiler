# [최종 보고서] 실시간 처리 속도 최적화 — 멀티스레드와 성능 측정

- 프로젝트명: 테니스공 실시간 검출 및 파이프라인 최적화 (Level 4 ★★★★☆)
- 권장 인원 / 기간: 2~3명 / 5일 (Day 1 ~ Day 5)
- 목표 성능: Jetson Orin Nano Super 기준 20 FPS 이상 / PC 기준 30 FPS 이상 달성
- 주요 제출물: pipeline_v1.py, pipeline_v2.py, pipeline_v3.py, benchmark.py, fps_comparison_table.csv, fps_benchmark_graph.png

## 1. 프로젝트 개요 및 공통 처리 흐름

본 프로젝트는 알고리즘/모델의 변경 없이 처리 구조 개선(멀티스레드, Downscaling, N-Frame Skip, ROI)만으로 2~3배 이상의 FPS 향상을 이끌어내고, 이를 자동화된 벤치마크 환경으로 증명하는 엔지니어링 프로젝트입니다.

### 🔄 공통 처리 파이프라인 (Pipeline Flow)

1. 전처리 (Preprocess): 입력 프레임 해상도 축소 (scale_factor=0.5) 및 가우시안 블러 처리
2. 검출 (Detection): HSV 색상 공간 변환 후 초록/노랑 범위 마스킹 (cv2.inRange)
3. 후처리 (Postprocess): 모폴로지 연산 (MORPH_OPEN/CLOSE), 외곽선 추출, 모션 블러 대응 단일 객체 선별
4. 결과 그리기 (Draw): 역배율 (1.0 / scale_factor) 복원 좌표 적용 및 원본 프레임 상 바운딩 박스/텍스트 렌더링

## 2. 세 가지 버전 파이프라인 구현 성과

### 📌 버전별 구조

- pipeline_v1.py (단순 반복): 단일 스레드 동기식 구조. 프레임 읽기-전처리-검출-후처리-렌더링이 순차적으로 수행됨.
- pipeline_v2.py (멀티스레드): threading.Thread와 queue.Queue(maxsize=2)를 도입하여 프레임 읽기 I/O 병목을 제거함.
- pipeline_v3.py (최적화 적용): Downscale, N-Frame Skip, ROI, Fast Interpolation (INTER_NEAREST) 기법을 조합하여 최대 FPS 도출.

### 💡 주요 핵심 구현사항

1. 객관적 Benchmark 환경 구축
   - 인위적인 대기 시간(time.sleep 및 절대 시간 동기화)을 완전 제거하고 cv2.waitKey(1) 기반의 최대 처리 속도 측정 환경 구성.
2. 정교한 좌표 역변환 (Inverse Scaling)
   - 축소된 해상도(0.5배)에서 검출된 사각박스 좌표 (x, y, w, h)에 역배율(inv_scale = 1.0 / scale_factor)을 정확히 곱해 원본 해상도 프레임 상에 일치시킴.
3. 자동화된 벤치마크 시스템 (benchmark.py)
   - 해상도 3종 × 버전 3종 조건별 60초간 3회 반복 측정 후, 평균 및 표준편차를 산출하여 pandas 데이터프레임 집계 및 matplotlib 그래프 자동 저장 기능 구현.

## 3. 발생한 주요 문제 및 해결 방법 (Troubleshooting)

### ① 최적화를 적용해도 FPS가 일정 수치로 고정되는 현상
- 원인: 영상 재생 속도 맞춤용 time.sleep() 대기 로직이 전체 파이프라인의 연산 속도를 강제로 상한선에 가두어 둠.
- 해결: 대기시간 연산 코드 제거 후 cv2.waitKey(1)로 최소 버퍼 갱신만 수행하여 하드웨어가 낼 수 있는 최대 FPS 산출.

### ② 해상도 축소 후 박스 위치가 공과 안 맞거나 밀림
- 원인: Downscaling 상태(0.5배)에서 검출된 좌표가 원본 해상도 프레임 상의 좌표로 역변환되지 않음.
- 해결: inv_scale = 1.0 / scale_factor 변수를 선언하고, 검출된 중심점 및 Bounding Box 좌표에 inv_scale을 곱해 정수로 변환 후 원본 위에 렌더링.

### ③ 속도가 빠른 공 추적 시 박스 뒤처짐 및 ROI 상실 (박스 안 쳐짐)
- 원인:
  1. 공이 날아가며 발생한 모션 블러(잔상)로 인해 완벽한 원 형태를 잃어 엄격한 원형도(circularity > 0.6) 조건에서 탈락함.
  2. ROI 탐색 마진이 좁아 빠른 공이 탐색 영역 밖으로 이탈함.
- 해결:
  - 원형도 기준 대신 종횡비(aspect_ratio: 0.3 ~ 3.0) 조건을 도입하여 찌그러진 잔상 공도 검출되도록 완화.
  - ROI 검출 마진을 확장(80px)하고, 공을 놓칠 경우 last_results = None 예외처리를 통해 다음 프레임에서 전체 화면 검출로 자동 복귀하도록 수정.

### ④ 노이즈 완화 후 배경 잡음으로 인한 '박스 폭탄' 발생
- 원인: 검출 조건 완화 시 배경의 초록 빛깔 요소(코트, 조명 등)가 전부 외곽선(Contour)으로 인지됨.
- 해결: 검출된 외곽선 중 면적(area)이 가장 큰 유력 후보 1개(best_candidate)만 추출하는 단일 객체 선별 알고리즘을 반영하여 박스 난립 차단.

## 4. 성능 측정 및 실험 결과 분석

### 📊 해상도 3종 × 버전 3종 FPS 비교표 (3회 측정 평균 ± 표준편차)

| 해상도 (Resolution) | Version ① (단순 반복) | Version ② (멀티스레드) | Version ③ (최적화 적용) | Performance 향상 폭 |
| :---: | :---: | :---: | :---: | :---: |
| **640 × 480** | 42.5 ± 1.2 FPS | 58.1 ± 1.8 FPS | **118.4 ± 2.5 FPS** | **약 2.78배 향상** |
| **1280 × 720** | 18.2 ± 0.8 FPS | 26.4 ± 1.1 FPS | **52.3 ± 1.4 FPS** | **약 2.87배 향상** |
| **1920 × 1080** | 8.4 ± 0.5 FPS | 12.1 ± 0.7 FPS | **31.8 ± 0.9 FPS** | **약 3.78배 향상** |

> 결과 요약: 1080p 고해상도 환경에서 V1은 8.4 FPS로 실시간 처리가 불가능했으나, V3 최적화를 통해 31.8 FPS를 달성하여 PC(30 FPS) 및 Jetson Orin Nano(20 FPS) 목표치를 모두 상회함.

## 5. [교과 14/15 공유용] 20 FPS 만들기 최적화 체크리스트

다음 프로젝트 및 다른 팀이 실시간 성능을 즉시 확보할 수 있는 핵심 가이드라인입니다.

- [x] 1. I/O와 연산의 분리 (멀티스레드 큐 적용)
  - 카메라/비디오 프레임 읽기(cv2.VideoCapture.read)와 연산을 별도 스레드로 분리.
  - queue.Queue(maxsize=2)를 설정하여 연산이 밀릴 때 오래된 프레임을 버리고 최신 프레임을 유도 (지연 누적 방지).
- [x] 2. 파이썬 GIL과 OpenCV의 특성 활용
  - Python의 GIL(Global Interpreter Lock)에도 불구하고, OpenCV 내부 연산 및 I/O 대기 시에는 GIL이 해제되므로 스레드 분리만으로 30~40% 이상의 성능이 상승함.
- [x] 3. Downscale 연산 후 좌표 역복원 (Scale Factor)
  - 전처리/검출은 0.5배 이하 축소 프레임에서 진행하고, 최종 바운딩 박스 표시 때만 1.0 / scale_factor를 곱해 원본 크기로 렌더링.
- [x] 4. ROI (관심 영역) 국소 탐색 & 예외 처리
  - 이전 프레임 객체 위치 중심으로 마진(80px)을 두어 마스킹 범위를 국소화함.
  - 빠른 객체 이탈을 대비해 검출 실패 시 다음 프레임에서 전체 화면으로 자동 전환되는 방어 코드 포함 필수.
- [x] 5. 모션 블러 대응 및 Max Area 후보 단일 선별
  - 고속 이동 시 엄격한 원형도(circularity) 대신 종횡비(aspect_ratio) 조건을 적용.
  - 여러 잡음 박스가 뜰 경우 면적(area)이 가장 큰 Candidate 1개만 선택하여 렌더링함으로써 배경 노이즈 완전 차단.
